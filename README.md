# FE Study Deck

基本情報技術者試験（科目A・科目B）の4択問題を学習する、GitHub Pages対応の静的Webアプリです。HTML、CSS、JavaScript、JSONだけで動作し、ログインやバックエンドは必要ありません。

現在は科目A 340問、科目B 160問の合計500問を収録しています。既存250問のIDと内容を維持し、`core-03`として250問を追加しました。問題データとアプリ本体は分離しているため、分野別・追加バッチ別のJSONファイルを増やして1000問以上へ拡張できます。

## 主な機能

- 全問題、科目A、科目B、カテゴリ・サブカテゴリ別の出題
- 10問、20問、30問から出題数を選択（不足時は利用可能な問題数まで出題）
- ランダム出題、過去に間違えた問題から出題、苦手分野優先出題
- 1問ごとの正誤判定、正答、解説表示
- 回答後の選択肢ロック
- 正解数、正答率、分野別成績の集計
- 結果画面での誤答内容と解説の確認
- 今回間違えた問題だけの復習、同じ条件での再挑戦
- `localStorage` による端末内の学習履歴保存とリセット
- 読み込み時と開発用スクリプトによる問題データ検証
- SVG構成図、構造化テーブル、科目Bの長文擬似言語表示
- PC・スマートフォン対応、キーボード操作と色だけに依存しない正誤表示

## 新しい問題を追加する方法

### 1. 追加先のJSONファイルを決める

既存分野へ追加するときは、対応する `data/A/*.json` または `data/B/*.json` の `questions` 配列に問題オブジェクトを追加します。

例として、科目Aの基礎理論なら `data/A/basic-theory.json` です。

```json
{
  "schemaVersion": 1,
  "questions": [
    {
      "id": "A0025",
      "exam": "A",
      "category": "テクノロジ系",
      "subcategory": "基礎理論",
      "difficulty": 2,
      "question": "ここに問題文を記述します。",
      "choices": [
        "選択肢A",
        "選択肢B",
        "選択肢C",
        "選択肢D"
      ],
      "correct": 0,
      "explanation": "正解の理由と、必要に応じて他の選択肢が誤りである理由を記述します。"
    }
  ]
}
```

追加時の注意点は次のとおりです。

1. `id` は全問題を通して重複しない値にします。科目Aは `A0001`、科目Bは `B0001` のような形式を推奨します。
2. `choices` は必ず4個にします。表示順がA、B、C、Dに対応します。
3. `correct` は **0始まりの配列index** です。Aが `0`、Bが `1`、Cが `2`、Dが `3` です。
4. `difficulty` は `1`（易しい）から `5`（難しい）の整数にします。
5. `question` と `explanation` は空にしないでください。
6. JSONでは、最後の項目の後ろにカンマを付けないでください。

### 2. 新しいファイルを追加する場合

問題数が増えて一つの分野ファイルが管理しにくくなった場合は、同じ分野を複数ファイルに分割して構いません。例えば次のように作成できます。

```text
data/A/security-01.json
data/A/security-02.json
```

作成後、`data/categories.json` の `questionFiles` にそれぞれを登録します。

```json
{
  "path": "./A/security-02.json",
  "exam": "A",
  "category": "テクノロジ系",
  "subcategory": "セキュリティ"
}
```

`path` は `data/categories.json` から見た相対パスです。GitHub Pagesのサブディレクトリ公開でも動作するよう、先頭 `/` の絶対パスは使用しないでください。

### 3. データを検証する

ブラウザで読み込むたびに、アプリは次を検証します。不正な問題は出題対象から除外し、開発者コンソールに `A0023: choicesが4個ではありません` のようなメッセージを表示します。

- `id` の重複
- `choices` が4個か、空の選択肢がないか
- `correct` が0〜3の整数か
- `question` と `explanation` が空でないか
- `exam`、`category`、`subcategory` が空でないか
- `difficulty` が1〜5の整数か

Node.jsが使える開発環境では、公開前にブラウザを開かず一括検証できます。Node.jsはアプリの実行やGitHub Pages公開には不要です。問題の内容、誤答、解説の作り方は `docs/question-authoring-guide.md` に従ってください。

```powershell
node tools/validate-data.mjs
node tools/audit-questions.mjs
node tools/verify-answer-keys.mjs
```

現在のデータでは `問題データ検証: 500問、エラーはありません` と表示されます。監査スクリプトは科目・分野・難易度・正解位置の分布に加え、ID重複・欠番、目録への未登録ファイル、選択肢重複、図版参照切れ、表の列数、長文コード行数、解説中の正解記号との矛盾、問題文の完全重複・近似重複を確認します。正答回帰検証では、計算・擬似言語143問を別工程で解き直した結果と現在の正解選択肢を照合します。エラーがある場合は終了コード1になります。

## 問題データ仕様

| 項目 | 型 | 必須 | 内容 |
|---|---|---:|---|
| `id` | string | 必須 | 全ファイルで一意の問題ID |
| `exam` | string | 必須 | 科目識別子。現在は `A` または `B` |
| `category` | string | 必須 | 大分類。例：`テクノロジ系` |
| `subcategory` | string | 必須 | 小分類。例：`基礎理論` |
| `difficulty` | integer | 必須 | 1〜5 |
| `question` | string | 必須 | 問題文 |
| `choices` | string[] | 必須 | A〜Dの順に並べた4個の選択肢 |
| `correct` | integer | 必須 | 正解の0始まりindex（0〜3） |
| `explanation` | string | 必須 | 回答後に表示する解説 |
| `visual` | object | 任意 | `type: "svg"`、相対`src`、代替説明`alt` |
| `table` | object | 任意 | `headers`と同じ列数の`rows`を持つ表 |
| `format` | string | 任意 | `standard` または `long-code` |
| `code` | string | 任意 | 改行を含む擬似言語。`long-code`は10～30行 |

図版は `assets/questions/問題ID.svg` を基本とし、`src`には `assets/questions/A0198.svg` のようなGitHub Pagesで解決できる相対パスを指定します。外部URL、先頭`/`、data URLは使用しません。将来、必要になった時点で `tags`、`sourceType`、`createdAt`、`updatedAt` なども追加できます。

## 分野・別試験を追加する方法

新しい分野は、次の手順で追加できます。

1. 分野用のJSONファイルを `data` 以下に作る。
2. 各問題の `exam`、`category`、`subcategory` を設定する。
3. `data/categories.json` の `questionFiles` にファイル情報を追加する。
4. 検証スクリプトを実行する。

トップ画面のカテゴリ・サブカテゴリ選択肢は、読み込んだ問題データから自動生成されます。HTMLやJavaScriptへの選択肢追加は不要です。

別の4択試験へ流用する場合も、同じ必須項目を持つJSONを用意できます。現在の画面タイトルは基本情報技術者試験向けなので、`index.html` のタイトル・説明・見出しだけを変更してください。出題、履歴、結果集計のモジュールはそのまま利用できます。

## ローカルでの動作確認

ブラウザで `index.html` を直接開く `file://` 方式では、ブラウザのセキュリティ制限により `fetch` でJSONを読み込めないことがあります。プロジェクトのルートディレクトリで簡単なローカルサーバーを起動してください。

Python 3の場合：

```powershell
python -m http.server 8000
```

その後、ブラウザで `http://localhost:8000/` を開きます。停止するときはサーバーを起動した画面で `Ctrl + C` を押します。

VS Codeを利用している場合は、Live Serverなどの静的サーバー拡張でも確認できます。

## GitHub Pagesで公開する方法

1. このフォルダ一式をGitHubリポジトリへコミットしてプッシュします。
2. GitHubのリポジトリ画面で **Settings** → **Pages** を開きます。
3. **Build and deployment** のSourceで **Deploy from a branch** を選びます。
4. 公開するブランチ（通常は `main`）とフォルダ `/ (root)` を選び、保存します。
5. デプロイ完了後に表示されるURLを開きます。

全てのCSS、JavaScript、JSON参照は相対パスなので、`https://ユーザー名.github.io/リポジトリ名/` のようなプロジェクトページでも動作します。ビルド処理やGitHub Actionsは必須ではありません。

## localStorageに保存する内容

キー名は `choiceQuiz.learningHistory.v1` です。次のJSONを端末のブラウザ内だけに保存します。

- `totalAnswers`: 累計回答数
- `totalCorrect`: 累計正解数
- `questions`: 問題IDごとの回答回数、正解回数、不正解回数、最終回答日時
- `mistakeIds`: 一度でも間違えたことのある問題ID
- `fields`: カテゴリごとの回答数と正解数
- `updatedAt`: 履歴の最終更新日時

履歴は外部へ送信されません。別の端末や別ブラウザとは共有されず、ブラウザのサイトデータを削除した場合も消去されます。トップ画面の「履歴をリセット」では確認後にこのキーを削除します。

## 苦手分野優先出題について

現在の簡易適応型出題は、カテゴリ別の正答率が低い問題と、問題別の誤答回数が多い問題の抽選重みを高くします。未回答問題にも小さな加点を行います。重み付き抽選は復元なしで行うため、一つの学習セッション内で同じ問題が重複出題されることはありません。

将来、別の出題ロジックへ差し替える場合は `js/quiz.js` の選択処理へ新しい方式を追加し、`app.js` からモードを渡します。問題データや結果集計の変更は不要です。

## 収録問題について

初期30問、`*-core-01.json`の100問、`*-core-02.json`の120問に、`*-core-03.json`の250問を追加しています。IPA「基本情報技術者試験（レベル2）シラバス Ver.9.2」を学習範囲の基準とし、段階的な難易度、自然な誤答、科目Bの擬似言語・状況判断を重視したオリジナル問題です。公開問題の文章や選択肢は複製していません。

500問版では次の12分野を扱います。

- ヒューマンインタフェース・マルチメディア
- システム開発技術
- システム監査
- 企業活動・法務
- 基礎理論、コンピュータシステム、アルゴリズムとプログラミング
- データベース、ネットワーク、セキュリティ
- プロジェクト・サービスマネジメント、経営戦略・システム戦略

追加250問のうち科目Aは150問、科目Bは100問です。追加分にはSVG図28問、表問題161問があり、図表付き問題は重複を除いて189問です。科目Bの追加アルゴリズム80問は、短い標準問題30問と10～30行の長文擬似言語50問に分けています。

今後の追加では `docs/question-authoring-guide.md` の品質チェックを維持してください。750問・1000問へ進む前に、各小分類の深さ、問題別正答率、誤答選択肢の選択率、難易度体感を確認し、制度やシラバスの改訂時には内容を再点検してください。
